# Security Policy

We take the security of Obsidian Secure seriously. If you believe you have found a security vulnerability, please review the security policy below for guidance on reporting it.

---

## Supported Versions

Only the latest release (v1.0.x and subsequent minor/major updates) on the `main` branch of the official repository is supported with security updates. 

| Version | Supported |
| :--- | :--- |
| 1.0.x | :white_check_mark: Yes |
| < 1.0.0 | :x: No |

---

## Reporting a Vulnerability

**Please do not report security vulnerabilities via public GitHub issues.**

Instead, please report security issues through the following channels:
1. **GitHub Security Advisory**: Propose a private draft advisory via the repository's "Security" tab -> "Advisories" -> "New Advisory".
2. **Dedicated Security Contact**: If you cannot use GitHub Advisories, please email the security maintainer at the placeholder security inbox: `security-contact@example.com` (this address will be updated to a monitored address upon release).

### Please include the following details in your report:
- A description of the vulnerability and its potential impact.
- Step-by-step instructions (with proof-of-concept scripts or payloads, if available) to reproduce the issue.
- Details of the environment used to reproduce the issue.

---

## Responsible Disclosure Policy

When reporting a vulnerability, we ask that you follow these responsible disclosure practices:
- Give us reasonable time to investigate and remediate the issue before making any details public.
- Do not exploit the vulnerability (such as stealing data, accessing other users' files, or causing denial of service).
- Do not interact with or compromise other users' accounts or data during security testing.
