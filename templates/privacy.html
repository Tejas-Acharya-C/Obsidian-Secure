verified_user Zero-Knowledge Architecture Overview

Obsidian Secure is designed around client-side end-to-end encryption (E2EE). All file and message payloads are encrypted directly inside your web browser using AES-256-GCM before transmission. Decryption keys are appended exclusively via URL hash fragments (#key=...). Because standard web browsers do not send hash fragments in HTTP requests to servers, Obsidian Secure operates with zero server-side key custody.

1. Account Data & Credentials

Account registration is optional for recipients and is required only for senders who wish to create, manage, and revoke E2EE share links. When an account is created, we store:

  • Username: Your alphanumeric user identifier.
  • Password Hash: Passwords are hashed server-side using PBKDF2 with SHA-256 (600,000 iterations). Plaintext passwords are never stored or logged.
  • Account Preferences: Optional settings such as display alias, Ghost Mode (filename masking), and default expiration policies.

2. Uploaded Payloads & Retention

Files uploaded to Obsidian Secure are stored as raw encrypted ciphertext blobs paired with a 12-byte random Initialization Vector (IV). The host server cannot read or inspect payload contents.

  • Automatic Expiry: Share links expire automatically after a duration configured by the sender (ranging from 1 hour to 7 days).
  • Background Cleanup: When a share expires or is manually revoked, database metadata and physical storage blobs are permanently purged.
  • Self-Destruct Messages: Ciphers configured with Burn-On-Read are deleted from database storage immediately after recipient decryption.

3. Rate Limiting & Security Logs

To prevent brute-force attacks and service abuse, we maintain IP-based rate limit logs:

  • Login Attempts: Failed login attempts are logged by IP address (limited to 5 attempts per 15 minutes).
  • Registration Attempts: Registration attempts are logged by IP address (limited to 5 attempts per hour).
  • Session Cookies: Active logins use HttpOnly, SameSite=Lax, and Secure session cookies.

4. Third-Party Analytics & Tracking

Public web pages (/ and /privacy) offer optional Google Analytics 4 (GA4) integration for public website traffic measurement. Under Basic Consent Mode, no analytics scripts or tracking cookies are loaded until you explicitly click “Accept Analytics” on the consent banner. If you decline or take no action, zero network requests or analytics cookies (_ga) are initiated. Private file transfers, dashboard activities, and encrypted payload operations omit tracking scripts entirely.
